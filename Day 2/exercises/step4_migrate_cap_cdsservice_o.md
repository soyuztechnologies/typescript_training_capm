Each service folder contains:

- **`index.d.ts`** — TypeScript type declaration files (pure types)
- **`index.ts`** — Runtime definitions for entities (classes/interfaces)
- **`types.ts`** — Helper type utilities

These are **auto-generated** — don't edit them. When you update your `.cds` files, re-run `cds-typer "*"` to regenerate.

## 📋 Cheat Sheet

| # | Plain JS | TypeScript | Why |
|---|----------|-----------|-----|
| 1 | `const cds = require('m')` | `import cds from 'm'` | ES default import |
| 2 | `const { a } = require('m')` | `import { a } from 'm'` | named import |
| 3 | `module.exports = class X {}` | `export default class X {}` | default export |
| 4 | `cds.entities('Svc')` | `import { E_ } from '#cds-models/Svc'` | typed entities — **use the plural `_` class** |
| 5 | `a && a.b && a.b.c` | `a?.b?.c` | optional chaining |
| 6 | `x \|\| {}` | `x ?? {}` | nullish fallback |
| 7 | read an unknown property | `(x as Record<string, unknown>).prop` | assert a bag of unknown keys |
| 8 | query with custom columns | `await SELECT… as Array<{…}>` | assert the projected shape |
| 9 | force a type | `value as unknown as T` | double assertion (rare) |
| 10 | handler data might be missing | `if (!data) return` | narrow away `\| undefined` |

## The `cds-typer` Naming Rule

For each entity, `cds-typer` generates **two** classes:

| Class | Meaning | Use it for |
|---|---|---|
| `ProductSet` | one **row** (singular) | a type for a single record |
| `ProductSet_` | the **collection** (`extends Array<ProductSet>`) | the entity you pass to CAP APIs |

> [!TIP]
> *Concept — singular vs. plural: CAP's handler and query APIs are typed around `ArrayConstructable`, which is the plural `_` class. Always pass the `_` form to `before` / `after` / `on` and to `SELECT.from` / `tx.update` / `tx.read`. cds-types then unwraps it for you — `before('CREATE', ProductSet_)` gives a single-row `req.data`, while `after('READ', ProductSet_)` gives the array.*

> [!CAUTION]
> **The biggest gotcha:** `ProductSet_` is the **class**. The actual rows are the **first argument of your handler callback** (`(products, req) => …`). Call `.map()`, `.find()`, flatten, etc. on *that argument* — never on the class.

    // register handlers…

<sub>code by anubhav trainings</sub>

> [!TIP]
> *Concept — what `init() { … return super.init() }` does: `cds.ApplicationService` is CAP's base class; its `init()` performs the framework's own wiring. You override `init()` to register your `before` / `after` / `on` callbacks (which fire later, per request — `init()` itself runs once at startup). `super.init()` calls the parent's original `init()` to finish booting, and because it returns a Promise, returning it lets CAP await your service being ready.*

## Step 4.4 — Use the Data Argument, Not the Class

Cheat-sheet rows 8 and 10.

```ts
this.after('READ', ProductSet_, async (products, req) => {
  if (!products) return                                   // row 10: drop | undefined

  const rows = project(flattenPayload(products), ['ProductId', 'Description', 'Price'])
  const ids = products.map(p => p.ProductId)              // map the DATA, not ProductSet_

  const partnerCount = await SELECT.from(ItemsSet_)        // plural class in CQL too
    .columns('ProductId', { func: 'count', as: 'count' })
    .where({ ProductId: { in: ids } })
    .groupBy('ProductId') as Array<{ ProductId: string; count: number }>   // row 8

  for (const p of products) {
    const partner = partnerCount.find(pc => pc.ProductId === p.ProductId)
    p.soldCount = partner ? partner.count : 0
  }
})
```

<sub>code by anubhav trainings</sub>

> [!TIP]
> *Concept — control-flow narrowing: after `if (!products) return`, TypeScript knows `products` can no longer be `undefined` below that line, so `flattenPayload(products)`, `products.map(...)`, and the `for…of` loop all type-check. The `as Array<{ ProductId: string; count: number }>` assertion gives a shape to a custom-column query result, which the runtime cannot type precisely.*

## Step 4.6 — The Error Handler

```ts
this.on('error', (err, req) => {
  const normalised = mapError(err)              // mapError already takes unknown
  const e = err as { code?: string; message?: string }
  e.code = normalised.code
  e.message = normalised.message
})
```

<sub>code by anubhav trainings</sub>

> [!TIP]
> *Concept — asserting writable properties: `err` may be typed as a plain `Error` (no `code` property), so we assert it to `{ code?: string; message?: string }` to declare the two fields we intend to write. `mapError(err)` itself needs no change because its parameter is already `unknown`.*

---

## Dependency Note — Your Utils Must Compose

`project(flattenPayload(...))` only type-checks if the two utility signatures line up: `flattenPayload(payload: unknown): unknown[]` must feed `project(rows: unknown[]): Record<string, unknown>[]`.

> [!CAUTION]
> **Special note:** If `flattenPayload`'s parameter is typed `undefined` instead of `unknown`, or `project` demands `Record<string, unknown>[]` instead of `unknown[]`, the chain breaks with a "not assignable" error. Keep `flattenPayload(payload: unknown)` and `project(rows: unknown[])` so the pipeline composes cleanly.

## Final File — `srv/CDSService.ts`

```ts
import cds from '@sap/cds'
import { ProductSet_, ItemsSet_ } from '#cds-models/CDSService'
import { flattenPayload, project } from '../utils/payload-transformer'
import { mapError } from '../utils/error-mapper'

export default class CDSService extends cds.ApplicationService {
  init() {

    this.before(['CREATE', 'UPDATE'], ProductSet_, async (req) => {
      console.log('Before CREATE/UPDATE ProductSet', req.data)
    })

    this.before('READ', ProductSet_, (req) => {
      const query = req.http?.req?.query ?? {}
      if ((query as Record<string, unknown>).simulateError === 'true') {
        throw new Error('Simulated runtime error while reading ProductSet')
      }
      if ((query as Record<string, unknown>).simulateError === 'type') {
        const broken = undefined as unknown as string
        return broken.toUpperCase()   // intentional runtime TypeError (the demo)
      }
    })

    this.after('READ', ProductSet_, async (products, req) => {
      if (!products) return

      const rows = project(flattenPayload(products), ['ProductId', 'Description', 'Price'])
      console.log('After READ ProductSet', rows)

      const ids = products.map(p => p.ProductId)

      const partnerCount = await SELECT.from(ItemsSet_)
        .columns('ProductId', { func: 'count', as: 'count' })
        .where({ ProductId: { in: ids } })
        .groupBy('ProductId') as Array<{ ProductId: string; count: number }>

      for (const p of products) {
        const partner = partnerCount.find(pc => pc.ProductId === p.ProductId)
        p.soldCount = partner ? partner.count : 0
      }
    })

    this.before(['CREATE', 'UPDATE'], ItemsSet_, async (req) => {
      console.log('Before CREATE/UPDATE ItemsSet', req.data)
    })

    this.after('READ', ItemsSet_, async (items, req) => {
      console.log('After READ ItemsSet', flattenPayload(items))
    })

    this.on('error', (err, req) => {
      const normalised = mapError(err)
      console.error('CDSService error', normalised)
      const e = err as { code?: string; message?: string }
      e.code = normalised.code
      e.message = normalised.message
    })

    return super.init()
  }
}
```
